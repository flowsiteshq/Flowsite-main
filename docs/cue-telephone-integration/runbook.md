# Cue Telephone Integration Runbook

## Status

The FlowSites application has a **non-live technical foundation** for a future Cue telephone agent. It does not create or configure an ElevenLabs agent, number, SIP trunk, 800.com forward, outbound call, SMS, payment, or public website widget. The public number remains **+1 888-933-3010**.

Cue’s existing `fs_cue_` key remains strictly read-only. A separate `fs_voice_` key, when deliberately created by an administrator, permits only phone-lead creation, an allowlisted lead update, and a limited call summary. It cannot read billing, manage staff, modify routing, send messages, or initiate payments.

## Deployment configuration

Set these server-only production variables after an administrator creates an ElevenLabs post-call webhook. Never put their values in source, a client page, an agent prompt, or this document.

| Variable | Purpose |
|---|---|
| `ELEVENLABS_WEBHOOK_SECRET` | Shared webhook secret generated by ElevenLabs; used with the official SDK against `ElevenLabs-Signature`. |
| `ELEVENLABS_API_KEY` | Optional ElevenLabs server credential for SDK initialization. It is never exposed to the browser. |

The signed endpoint is:

```text
POST https://flow-sites.com/api/integrations/elevenlabs/webhook
```

Only `post_call_transcription` events are accepted. The server verifies the exact raw request body using ElevenLabs’ official JavaScript SDK, checks the provider timestamp, and deduplicates the event with the conversation ID. It stores at most a limited provider-attributed summary in the call-event ledger; it does not store the raw transcript or audio recording.

## Agent webhook-tool configuration

Do not configure these endpoints until a staging/test-number review has passed. When that stage is approved, create one `fs_voice_` key in **Cue telephone readiness** and store it in ElevenLabs as a secret `Authorization: Bearer …` header.

| Endpoint | Allowed use |
|---|---|
| `POST /api/integrations/elevenlabs/tools/phone-leads` | Create a qualified phone lead only when the required business and contact fields have been collected. |
| `PATCH /api/integrations/elevenlabs/tools/phone-leads/:leadId` | Update only business/contact/status/follow-up fields explicitly allowlisted by the server. |
| `POST /api/integrations/elevenlabs/tools/calls/:providerCallId/summary` | Append an idempotent, provider-attributed call summary. |

Tool configuration must not include an endpoint that sends SMS, places calls, issues an invoice, creates a checkout session, changes a Stripe subscription, forwards a number, or changes staff access.

## Required test-number acceptance checks

Before considering an 800.com routing change, test on a separate approved number and capture the evidence below.

1. Verify a valid signed post-call event returns `200`; missing, malformed, and stale signatures return `401` and do not write a record.
2. Deliver the identical event twice and confirm that the second request reports a duplicate without a new lead, summary, or notification.
3. Use the voice key with every allowed endpoint and verify that unknown fields, a Cue read-only key, a revoked key, and an expired key are rejected.
4. Verify the voice agent identifies itself as an AI, stays within approved FlowSites knowledge, and offers a human handoff rather than making unsupported guarantees.
5. Verify human transfer reaches a real monitored number and cannot loop back into the same AI route.
6. Verify the number owner, call hours, voicemail fallback, recording/transcript retention, applicable consent, and rollback action are documented.

## 800.com decision

Do not change the live 800.com route until the signed-in account confirms whether it provides a compatible SIP trunk. If it does, use the verified SIP route in a staged environment. If it provides standard forwarding only, use an independently approved test destination first. If there is no compatible path, retain the current configuration and do not imitate SIP with unverified settings.

## Rollback

Revoke the active `fs_voice_` credential in the staff page, disable the ElevenLabs webhook, and restore the prior 800.com forwarding rule. The application preserves provider-event audit records but does not persist recordings or raw transcripts.
